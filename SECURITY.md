# Security Policy / 安全策略

## Supported Versions / 支持版本

We release security fixes for the latest `main` branch and the most recent tagged release.

我们为最新的 `main` 分支与最近的正式发布版本提供安全修复。

## Reporting a Vulnerability / 报告漏洞

**Please do NOT report security vulnerabilities through public GitHub issues.**

**请不要通过公开 GitHub Issue 报告安全漏洞。**

Preferred channels / 推荐渠道：

1. **GitHub Private Vulnerability Reporting (私密漏洞报告)**
   Repository maintainers can enable it under:
   `Settings → Code security → Private vulnerability reporting`
   一旦维护者开启该选项，报告者即可通过仓库 Security 标签页的 "Report a vulnerability" 私密提交。
2. **Email / 邮件**
   Contact the maintainers listed in the repository README for a private security email.

## What to include / 报告请包含

- Affected file(s) and line(s) / 受影响的文件与行号
- Reproduction steps or PoC / 复现步骤或概念验证
- Impact assessment / 影响评估
- Suggested fix (optional) / 修复建议（可选）

## Safe harbor / 安全港

We will not pursue action against researchers who report vulnerabilities responsibly,
make a good-faith effort to avoid privacy violations and service disruption, and
give us reasonable time to fix issues before any public disclosure.

对以负责任方式报告漏洞、善意避免隐私侵害与服务中断、并在公开披露前给予合理修复时间
的安全研究者，我们不会采取任何法律或管理行动。

## Acknowledgements / 致谢

Security researchers who responsibly disclose issues will be credited in the advisory
when it is published.

负责任披露的安全研究者将在安全公告发布时获得致谢。
